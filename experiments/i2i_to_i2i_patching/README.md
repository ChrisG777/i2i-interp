# i2i → i2i text-token activation patching

Captures activations from a **source** i2i run and patches the **text-token** slice into a **target** i2i run, sweeping across all 32 blocks. The two runs must share `instruction` (relax with `--allow-mismatched-instruction`) and must use a different ref (one of `real_ref_name` / `source_image_path` / `ref_seed`). `noise_seed` is not required to match — paper-scale pair sets deliberately use cross-seed pairings. Invariants are enforced by `I2IToI2IRunner.run_pair(source, target)`.

## Token slice patched

Slice boundaries come from the per-task `TokenLayout` (see [Patching framework](../README.md#patching-framework)).

| Category | MM block slice  | Single block slice           |
|----------|-----------------|------------------------------|
| `text`   | `txt_stream`    | `hidden[:, :text_end, :]`    |

`--text-token-mode` (repeatable; default `all`) selects which positions inside the text slice get patched:

| Mode           | Positions                                       | Flat-layout filename          |
|----------------|-------------------------------------------------|-------------------------------|
| `all`          | full 512-token slice                            | `patched.png`                 |
| `padding_only` | Qwen3 padding positions (complement of content) | `patched_text_padding.png`    |
| `content_only` | content positions (the real prompt tokens)      | `patched_text_content.png`    |

Pass any combination (e.g. `--text-token-mode all padding_only content_only`) to run multiple variants in the same per-pair dir, sharing reference + baselines. The per-mode skip means a re-run that adds a new variant only generates the new flat-filename PNG.

## Pair sets

Three families ship with checked-in `pairs.txt`, regenerable via [`build_pairs_color.py`](build_pairs_color.py), [`build_pairs_style.py`](build_pairs_style.py), and [`build_pairs_dreambench_humans.py`](build_pairs_dreambench_humans.py):

| Family | Pairs | Pairing rule |
|---|---:|---|
| `single9_4step_color` | 448 | 8 objects × 56 directed `(color_a, color_b)` per object; cross-seed `s_i` → `s_{(i+1)%5}`. |
| `mm7_4step_style_to_real` | 450 | 18 subjects × 5 prompts × 5 seeds; cross-seed style `s_i` → real `s_{(i+1)%5}`. |
| `mm7_4step_dreambench_humans` | 450 | 5 shared prompts × 90 directed `(subject_a, subject_b)` per prompt; cross-subject pairs use distinct `noise_seed`s. |

All three pass the runner's invariants without `--allow-mismatched-instruction`.

## Output layout

```
results_v4/i2i_to_i2i_patching/<source_task_id>__<target_task_id>/<run_timestamp>/
    task_metadata.json
    cli_args.json
    ref_source.png + ref_target.png
    source.png                # source i2i (with activation hooks)
    target_baseline.png       # target i2i with no patching
    target_t2i_clean.png      # target prompt + seed, no ref
    text_tokens/
        patched_<block>_to_<block>.png   # one per swept block (32 in a full sweep)
        grid.png
```

Per-block filenames use the compact `block_suffix` (`utils/flux2_klein.py`): MM blocks are `mm0`…`mm7`; single blocks are `single_mm0`…`single_mm23` (the established on-disk suffix — `transformer_blocks.` is a substring of `single_transformer_blocks.`). So block 17 (Single 9) is `patched_single_mm9_to_single_mm9.png`.

Grid panel: `[Source, Target (baseline), Target t2i clean, <one cell per source block>]`. `task_metadata.json` records both `source_instruction` / `target_instruction` and `source_noise_seed` / `target_noise_seed` so asymmetric runs are self-documenting.

## Transfer scope

`--block-range B B` selects a single block to patch (e.g. `--block-range 17 17` for Single 9). Under `--results-subdir` this is *flat layout*: each mode flattens to one `patched.png` (the paper headline cells). With no `--block-range` at all, the run sweeps every block into the nested `text_tokens/` layout (smoke/exploration runs).

## Usage

```bash
# Single pair
uv run python experiments/i2i_to_i2i_patching/i2i_to_i2i_patch.py \
    --pair manual_solid_yellow_couch manual_solid_blue_couch

# Paper-scale color pair (cross-seed; same instruction, different ref)
uv run python experiments/i2i_to_i2i_patching/i2i_to_i2i_patch.py \
    --pair solid_yellow_couch_s0 solid_blue_couch_s1

# Stress: different subjects (requires --allow-mismatched-instruction)
uv run python experiments/i2i_to_i2i_patching/i2i_to_i2i_patch.py \
    --pair customize_property_style_dog_frisbee_s0 \
           customize_property_style_capybara_hotspring_s0 \
    --allow-mismatched-instruction
```

## Padding-token dose-response ablation

Holds `--text-seq-len` at 512 and varies the **padding count** by varying prompt length: four nested levels targeting ~494 / ~322 / ~149 / ~0 padding tokens (each level's instruction is a strict word-prefix of the next longer one — the short instruction verbatim plus a token-calibrated prefix of the neutral `COLOR_FILLER` / `STYLE_FILLER`). Joint sequence length and RoPE range never change; only the content/padding split moves. If padding carries the transfer, `padding_only` should fall monotonically as padding disappears; a rising `content_only` would instead indicate spare capacity.

- **Build**: [`build_padding_ablation_tasks.py`](build_padding_ablation_tasks.py) → `data/tasks/{solid_color,style}_padding/tasks.jsonl` (120 / 100 rows per level); [`build_pairs_padding_ablation.py`](build_pairs_padding_ablation.py) → `pairs/single9_4step_color_p<NNN>.txt` (48 pairs) and `pairs/mm7_4step_style_to_real_p<NNN>.txt` (50 pairs), identical composition across levels so the dose-response is within-pair.
- **Generate**: [`scripts/reproduce_padding_ablation.py`](../../scripts/reproduce_padding_ablation.py) — 8 cells (`{color,style_to_real}_p<NNN>`), all three `--text-token-mode` variants, blocks Single-9 / MM-7. Supersedes the earlier 512-vs-1024 `--text-seq-len` ablation, which confounded padding count with total sequence length.
- **Judge**: `PADDING_ABLATION_JUDGES` (`scripts/judge/configs.py`) — 24 judges reusing the byte-identical family prompts (never mentioning prompt length); grouped per (family, level) for prompt-cache reuse.
- **Plot**: `uv run python scripts/plot_padding_ablation.py` → `paper_images/fig_padding_ablation/padding_ablation.{png,pdf}` — success rate vs padding count, one line per mode, one panel per family.

### Results (claude-sonnet-5 judge, 2026-07-26)

Not a padding dose-response but a **spare-capacity crossover**: the transferred property lives in whichever text slots are spare, not in padding positions per se. `padding_only` collapses as soon as content displaces it, `content_only` rises symmetrically to 100% at the full-length prompt, and the full-slice patch stays ≥82% throughout — so with a short prompt the spare capacity happens to be padding, which is what the paper's headline cells measure.

The content-span split sharpens this: `instruction_only` (the original short instruction's tokens) is at or near the floor everywhere, while `filler_only` (the appended neutral filler) tracks `content_only` almost exactly. The carrier is never the task-bearing tokens — it is whatever is semantically inert, padding or filler. The split is degenerate at p494, where the prompt *is* the instruction.

Token counts include the ~6 chat-template scaffold tokens; total text slots are always 512. Opus 4.7 agrees with Sonnet 5 on 96.9% of the 288 overlapping verdicts (color p494/p322, CSVs at the default `vlm_judge/` paths).

Color (Single-9, n=48/row):

| padding tok | content tok | all | padding_only | content_only | instruction_only | filler_only |
|---:|---:|---:|---:|---:|---:|---:|
| 494 | 18 | 100.0% | 97.9% | 0.0% | — | — |
| 322 | 190 | 100.0% | 2.1% | 20.8% | 0.0% | 8.3% |
| 149 | 363 | 100.0% | 0.0% | 35.4% | 0.0% | 31.2% |
| 0 | 512 | 100.0% | 0.0% | 100.0% | 0.0% | 100.0% |

Style (MM-7, n=50/row):

| padding tok | content tok | all | padding_only | content_only | instruction_only | filler_only |
|---:|---:|---:|---:|---:|---:|---:|
| 480-485 | 27-32 | 82.0% | 68.0% | 0.0% | — | — |
| 322 | 190 | 98.0% | 40.0% | 90.0% | 20.0% | 76.0% |
| 149-150 | 362-363 | 100.0% | 4.0% | 100.0% | 4.0% | 98.0% |
| 0-5 | 507-512 | 100.0% | 6.0% | 100.0% | 8.0% | 98.0% |

Note that style `instruction_only` is *near* the floor (4-20%) rather than exactly zero as in color, so "the instruction carries nothing" should be stated as "at or near zero" for that family.

**Negative result — the collapse cannot be rescued by patching harder** (a few pairs, qualitative). Widening the patch from 1 block to all 32 leaves `padding_only` flat (color p149: 0.15 -> 0.16 mean Lab transfer; couch pair 0.04 -> 0.05); a 32-block single-block scan finds no other depth where it works (Single-9 remains the best block); and dropping the style prompts' "A photograph of" opener does not help either. The same span lever *does* lift the `all`-token patch (0.66 -> 0.80), so the intervention works — there is simply no signal left in the padding band once the prompt is long. Caveat: the probe's Lab transfer fraction is a colour metric and is **only valid for the solid-colour family** — it reports large apparent gains on style that are scene/lighting changes, not stylization.
